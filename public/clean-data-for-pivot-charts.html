Data preparation guide

How to clean data before creating a pivot table or chart

Most confusing pivot-chart results begin in the source file. Use this checklist to turn an export or worksheet into a small, reliable data table.

Start with a table, not a report layout

A pivot table expects records. Each row should describe one transaction, event, person, product, or other observation; each column should describe one property of that record. A sales export might have Order Date, Region, Category, Sales, and Quantity. That structure is different from a presentation-ready report with a title at the top, merged headings, blank spacing rows, and a grand total at the bottom. Keep the report layout in a separate sheet or remove it from the upload copy.

Use one header row and make every header unique. Repeated names such as “Amount” can make field selection ambiguous, while blank names make it difficult to know what the tool is grouping. Prefer concise labels that state the data, such as “Order Date” rather than “Date” when several dates exist. If a worksheet contains several independent tables, export each one separately rather than selecting a large range that includes them all.

Remove rows that are already calculations

Subtotal and grand-total rows are a frequent cause of inflated pivot totals. They summarize records that are already present, so adding them again produces double counting. Remove total rows, percentage summaries, section headers, and notes before creating the pivot. A similar problem appears when a monthly export contains cumulative totals in addition to individual transactions; decide which level is the true source record and use only that level.

Also look for duplicate records. Duplicates are not always errors: two identical orders may be legitimate. Compare an identifier, date, and source context before deleting anything. The goal is not to make every row visually different; it is to make sure every row represents one valid observation exactly once for the question being asked.

Standardize categories and field types

Pivot tools group text exactly as it appears. “North,” “north,” and “North ” can become three separate categories, even though they mean the same thing. Correct spelling variants, extra spaces, inconsistent punctuation, and placeholder values such as “N/A” or “Unknown” before publishing a chart. If incomplete data must remain, give it an explicit, truthful category rather than allowing blank labels to hide the gap.

Check that amounts and quantities are numbers, not text. Currency symbols, commas, and percentage signs can vary by export. Dates also need attention: use a consistent date format and avoid mixing words, serial values, and free-form notes in one column. A data preview after upload is useful because it shows whether the browser recognized the intended field type before a calculation is applied.

Match the cleanup to the analytical question

Ask one question before configuring the pivot. For total sales by region, use Region and Sales, and decide whether returns, tax, discounts, or cancelled orders belong in the definition. For order count by month, verify that each row is an order rather than an order line. A technically correct sum can still be misleading if the source units and inclusion rules are unclear.

Filters should narrow a stated scope, such as one year, market, or product family. After filtering, check the number of included records and the grand total. Write the scope in the chart title or accompanying note. This makes a later reader less likely to compare charts that cover different periods or different definitions without noticing.

Verify before exporting

Build the pivot table first, then test it with a few source records. Compare the largest group, a small group, and the grand total. If the values look wrong, work backward: check the selected aggregation, active filters, duplicate records, subtotal rows, and field types. Only after the table is credible should you choose a chart. Use bars for category comparisons, lines for time trends, and pies only for a few parts of a genuine whole.

A reusable cleanup checklist

Before each new analysis, confirm that the range has one header row, each header is unique, each row is one record, and calculations such as subtotals are outside the range. Standardize categories, numbers, and dates; inspect the preview; then verify the pivot’s largest group, a small group, and grand total. Recording these checks creates a repeatable trail from source data to chart instead of relying on a result that cannot be explained later.
