What CSV transpose does

CSV transpose turns a row-oriented table into a column-oriented layout, or the reverse, by swapping rows and columns. The first row of your upload is treated as data like every other row, not as a special header that is dropped or kept fixed on the side. After transpose, what was row one becomes column one, row two becomes column two, and so on. If some rows in the original file are shorter than the widest row, the parser pads them with blank cells before rotating so every position is defined. The tool runs entirely in your browser: your file is not uploaded to a server for conversion. You pick a delimiter, run transpose, skim a preview of the first twelve rows of the result, then download the full transposed CSV with every row included. Input is expected to be UTF-8 text with a single header row only in the sense that you may have one; it is still rotated like any other line. Input delimiter choice affects how fields are split on read; comma, semicolon, tab, pipe and automatic detection are supported. Output uses commas. This page accepts CSV only, not Excel workbooks; use the Excel to CSV tool first if your data is in .xlsx or .xls format.

When transpose is useful

People use transpose when a report was exported with dates or categories across the top but analysis tools want one row per observation, or when a sensor log stores channels as rows and you need time in the first column instead. It is also handy for reshaping small matrices for charts, joining to another file that shares an ID in the first column, or comparing the same entities listed vertically in one file and horizontally in another. Because the operation is a straight geometric swap with blank padding, it does not interpret types: numbers and dates stay as the text that appeared in each cell. Transpose does not deduplicate columns, merge files, or fix header naming; it only reorients the grid you provide. If you need to combine several CSV exports into one long table, use the CSV merge tool after you have aligned headers manually or ensured each file uses the same header spelling. If you need live formula results from Excel rather than last-saved displayed values, re-save or calculate in Excel before export, because this tool never opens workbooks.

Step-by-step workflow

Start by preparing a UTF-8 CSV within the size and shape limits: up to ten megabytes per file, up to one hundred thousand data rows and one thousand columns in the source grid, with transposed output allowed up to two thousand columns. Open the transpose page, choose the delimiter that matches your file, and upload the CSV. Click transpose to parse all rows including the first line, pad short rows to the width of the longest row, build the rotated matrix, and render the preview limited to the first twelve result rows so the page stays responsive. Open the preview table to confirm that output row one matches the first input column read top to bottom, that quoting around commas or semicolons survived correctly, and that trailing empty fields did not collapse in a misleading way. When the layout looks right, download the CSV to get the complete transposed dataset with no row cap on export. Keep your original file unchanged as a backup. For wide inputs, remember the output row count equals the original column count; very wide files can become tall exports that are still valid CSV but heavy in spreadsheet apps.

How padding and rotation work

The implementation reads the file as delimited text, splits each line into fields using your selected delimiter with standard CSV quoting rules, and determines the maximum field count across all rows. Any row with fewer fields gets empty strings appended on the right until its length matches that maximum. Then for each original column index, the tool collects the value at that index from row zero, row one, row two, through the last row, and writes that collection as one new row in the output. The first input row becomes the first column of the output, while the first input column becomes the first output row. Blank pads matter when, for example, row five had only three fields but row one had six: positions four through six for row five are treated as empty before the swap, so the transposed columns that came from those positions still exist and show blanks where data was missing. Completely blank input records are skipped; otherwise the tool retains fields and it does not trim spaces inside fields unless your source already had trimmed values.

Concrete input and output example

Suppose you upload a comma-separated file with three rows and four columns, with no irregular widths. Row one is: alpha, beta, gamma, delta. Row two is: 1, 2, 3, 4. Row three is: x, y, z, w. After transpose with comma delimiter, you should see four rows. Row one becomes: alpha, 1, x. Row two becomes: beta, 2, y. Row three becomes: gamma, 3, z. Row four becomes: delta, 4, w. Notice how the first output row is the first column of the input read from top to bottom, not a copy of the old header row pinned separately. If the second input row were shorter, say only alpha, 1 with two fields while other rows still had four, padding would add two blank fields on that row before rotation, and the third and fourth output rows would include empty cells in the slot that came from those padded positions. Quoted fields containing commas stay single cells on both read and write; the downloaded file uses quoting when needed for a comma delimiter.

Checking results and delimiter choices

Always compare dimensions: output row count should equal the original column count after padding, and output column count should equal the original row count. Spot-check several cells by tracing back to the source coordinates: output at row i column j should equal input at row j column i when both use zero-based indexing on the padded grid. If every line in the preview looks like one giant field, the delimiter is probably wrong for your file, or the file uses a different encoding than UTF-8, which can produce parse errors or odd characters. If transpose fails immediately, read the error message: it may cite file size, row or column limits, parse failures, or encoding problems. The preview is only twelve rows; long files require scrolling in a local editor after download to verify the tail. Empty trailing delimiters at line ends create empty fields that participate in transpose the same as explicit values. Tabs and semicolons are common in European exports; pick the delimiter that matches the file rather than forcing comma. The default setting attempts to detect the input delimiter automatically.

Limits, failures, and related tasks

Hard limits are enforced before and during processing: ten megabytes maximum per file, one hundred thousand data rows and one thousand columns on input, and up to two thousand columns in the transposed output shape. Exceeding any limit returns a clear error and no download. Malformed quoting and unrecoverable parse errors stop the run with a message. Invalid UTF-8 can appear as replacement characters, so check the source and preview. Because work happens in the browser, extremely large grids may stress memory or tab performance even when within published caps. Transpose does not support .xlsx or .xls on this page; convert with the Excel to CSV tool, download UTF-8 CSV, then transpose here. To stack multiple CSV files by headers, use merge, not transpose. Merge requires consistent header rows and row widths across files; transpose leaves you with a single file in a new orientation. Neither transpose nor merge recalculates Excel formulas. For Excel sources, exported cached displayed values are what subsequent CSV tools see. If transpose is unsuitable because you only wanted to turn the first row into headers without rotating IDs, you need a different operation than full matrix transpose; this tool always rotates the entire rectangle including row one.

CSV format reference

CSV fields may contain commas or line breaks when quoted correctly. See the CSV format specification RFC 4180 for common conventions.

Frequently asked questions

Is the first row transposed?

Yes. Every row, including the first, is rotated.

What happens to short rows?

They are padded with empty cells to the width of the longest row.

How is transpose different from unpivot?

Transpose swaps the entire grid; unpivot turns selected columns into attribute and value rows.
