How to unpivot a wide CSV to long format

Upload a wide CSV, set delimiter, and confirm the header row. Designate one or more identifier columns that stay fixed on each output row, such as product id, store, or respondent id. Mark every column you want melted into values as unpivot targets; you need at least one identifier and at least one value column selected. All unselected columns are retained as identifiers. For each original data row, the tool emits one output row per selected value column, pairing the identifier cells with the column header name and the cell contents from that wide column. Blank cells in wide columns still produce a long row with an empty value field rather than skipping the combination. Preview shows up to twelve long rows; download includes the full unpivoted dataset with consistent long-form headers.

Worked example: quarterly sales columns

Wide input headers: Store, Q1_Sales, Q2_Sales, Q3_Sales. One data row: Store "North", Q1_Sales "100", Q2_Sales "150", Q3_Sales blank. With Store as the only identifier and all three quarter columns selected, output has three rows: North, Q1_Sales, 100; North, Q2_Sales, 150; North, Q3_Sales, empty value cell. A second data row for Store "South" with values 80, 90, 70 adds three more lines. Identifiers repeat per melted column by design. If you selected only Q1 and Q2, Q3 would remain as an identifier column. Two identifier columns such as Store and Region would both repeat on each melted row. Row multiplication factor equals the number of selected value columns times the number of input data rows, which guides file size expectations before download.

Identifier columns versus attribute names

Identifiers are dimensions you want repeated unchanged while each measure column fans out. Value column headers become entries in the attribute column of the long layout—often conceptually a variable name, period label, or question code. Cell text under each wide header becomes the value column entry without type coercion; numbers and dates remain text as in CSV. Selecting every non-id column unpivots the entire measure block; leaving descriptive static fields as identifiers keeps them on each long row for filtering later. Do not select the same column as both identifier and value. If two wide headers differ only by invisible whitespace, they produce two distinct attribute keys. Exact text rules apply: case and spaces in headers propagate to the long attribute field.

Delimiters, quotes, and empty wide cells

Mis-set delimiters break wide headers so melted names look like garbage fragments. Quoted headers with commas inside become single attribute labels when parsed correctly. Empty trailing columns in some exports still unpivot if selected, yielding long rows with blank values. Completely empty input rows are skipped on import and contribute nothing. A wide cell that contains only spaces is that literal string in the value column, distinct from empty unless your source truly left the field null between delimiters. Pipe- or tab-separated wide tables follow the same unpivot rules once delimiter is set. Very wide sheets with dozens of month columns create proportionally many long rows per identifier; ensure downstream tools can handle the expanded row count. Header row must be first; extra preamble rows will mislabel identifiers.

Local unpivot, scale, and download behavior

Unpivot executes in the browser without server upload. Memory use grows with input rows multiplied by selected value columns, so thousand-row files with hundreds of columns can become large long outputs. The preview of twelve rows helps verify attribute header naming and identifier repetition pattern before committing to a big download. Download delivers the complete long CSV, not preview-limited. No automatic aggregation or filtering runs after melt; one wide row always becomes exactly as many long rows as there are selected value columns unless you later dedupe or subset elsewhere. Session data clears when you leave unless saved. For regulated data, local melt avoids exposing wide extracts containing many attributes in one cloud pipeline step.

Checking long-format output

Validate by picking one identifier from the preview and tracing it through each attribute row you expect from wide headers. Count long rows for one input line; it should equal the number of value columns ticked. Blank wide cells should appear as long rows with empty value fields if those columns were selected, confirming blanks were not dropped silently. Attribute names match the displayed column labels; empty or duplicate headers are renamed on import. Identifiers on all melted lines from the same source row must be identical across non-id fields. If row counts explode beyond expectation, you may have selected numeric id columns as values by mistake. If counts are too low, some wide columns may be unchecked or blank rows dominated import. Sort downloaded output by identifier then attribute to audit completeness against the wide source in a side-by-side review.

Why melt wide sheets and what to do after

Charting and many databases prefer one observation per row with a metric name column instead of sprouting period columns. Survey exports with one column per question unpivot for per-question counts or filtering. Panel data with years across the header becomes panel-long for regression prep. After unpivot, use count on the attribute column to see which measures exist per file, or dedupe on identifier plus attribute if wide export accidentally duplicated keys when stacked. You may still need type casting or date parsing outside this tool because values stay text. For reverse needs, pivoting long to wide is a separate manual or spreadsheet operation. Save melted CSV before further transforms. When only a subset of periods matters, select those value columns only to avoid extra long rows. Chain dedupe first if wide rows were duplicate records before melt would duplicate the entire long block.

CSV format reference

CSV can use quoted fields for commas, quotes, and line breaks. See the CSV format specification, RFC 4180, for details about common CSV conventions. Check the file's encoding and delimiter before processing.

Frequently asked questions

What happens to unselected columns?

They remain as identifier columns and are repeated on each output row.

Are empty values dropped?

No. Every selected cell produces an output row, including empty values.

How many rows will I get?

Each input row produces one output row for each selected column, up to the 300,000-row output limit.
