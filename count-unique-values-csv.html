How to count distinct values in a CSV column

Open the count tool on this page and load your file from disk. The browser parses the sheet without sending it to a server. The first row is treated as column headers, then pick the delimiter that matches your export: comma, semicolon, tab, or pipe. Blank lines in the file are ignored during import. Choose one column from the header list to analyze. Run the count after loading the data and choosing a column. The tool tallies how often each exact cell value appears, treats empty cells as their own category, and expresses each tally as a percentage of all rows in that column with two decimal places. The on-screen table shows a slice of the frequency list; use download to save the complete result set as CSV for sorting, filtering in another editor, or archiving.

Worked example: category column with blanks and near-duplicates

Suppose a five-row export has header Category and rows: Apple, apple, Banana, an empty cell, and Apple again. Case and spaces matter: Apple and apple are two separate values, not one merged label. Use a second column containing a record ID so that the row with an empty Category is not a completely blank row; that empty category contributes one occurrence. Frequency output would list Apple twice (two rows), apple once, Banana once, and blank once, with shares of 40%, 20%, 20%, and 20% respectively. If you expected a single “apple” total, the result is telling you the source data used inconsistent casing rather than merging variants. Check the five data rows in the source: five is the denominator and the sum of counts equals five.

What counts as the same value

Matching is literal text in the cell after the file is split into fields. Uppercase and lowercase letters differ, so US and us are two keys. Leading or trailing spaces inside the field are preserved, so "East " and "East" do not combine. Punctuation and internal spacing must match exactly. The tool does not trim, fold case, or normalize Unicode forms unless your source file already did. Empty cells are included in the frequency table as their own entry rather than skipped, which helps you see missing-data volume. Duplicate rows in the file each increment the same value’s count; this tool does not collapse duplicates unless you dedupe elsewhere first. If two values look identical on screen but split separately, inspect for hidden characters or delimiter misreads in the source file.

Headers, delimiters, and quoted CSV fields

Only the first row supplies column names used in the column list; data rows start on line two. If your vendor file has title rows above headers, strip those lines before upload or counts will attach to the wrong column. European spreadsheets often use semicolon as the field separator while English ones use comma; mis-guessing merges columns and produces nonsense distinct values. Tab- and pipe-delimited logs need the matching setting so commas inside text stay inside one field. Standard double-quote wrapping allows commas, semicolons, or line breaks within a single cell; the parser respects quotes so one marketing tag with commas does not become three pseudo-values. After processing, inspect the result and compare it with a few source rows. Wrong delimiter typically shows one ultra-wide column or many empty-looking columns.

Reading percentages and validating the total

Each percentage is that value’s row count divided by the number of data rows in the chosen column, scaled to one hundred and shown with two decimal places. Rounding can make printed percentages sum to ninety-nine point nine nine or one hundred point zero one; compare integer counts if you need an exact audit. A dominant single value with ninety-plus percent share often means a default code, placeholder, or bulk import error. A long tail of values each at zero point zero one percent may be typos, unit variants, or free text that should be bucketed upstream. Cross-check: sum of counts across all rows in the frequency table should equal the number of non-skipped data lines for that column. If blank appears with high share, plan imputation or filter rules before modeling. Re-run on a sibling column to confirm delimiter choice stayed correct.

When frequency tables help and sensible follow-up

Cardinality checks before joins show whether a key column is almost unique or heavily repeated. Survey and form exports benefit from seeing how often each option was chosen, including unanswered blanks. Inventory or SKU columns reveal duplicate codes versus true distinct products when you compare count output to business expectations. After counting, you might dedupe rows on a composite key if repeats explain skewed frequencies, or unpivot wide survey grids so each question becomes one column to count answers separately. For cleanup, use the frequency list to build a correction spreadsheet outside this site, then re-import. Saving the downloaded CSV gives you a stable snapshot for documentation. For keys meant to be unique, a single value with count greater than one flags dedupe candidates without manual pivot tables.

CSV format reference

CSV can use quoted fields for commas, quotes, and line breaks. See the CSV format specification, RFC 4180, for details about common CSV conventions. Check the file's encoding and delimiter before processing.

Frequently asked questions

Are blank values included?

Yes. An empty cell in a nonblank record is counted as a value. Completely blank records are skipped.

Are values case sensitive?

Yes. Apple and apple are counted separately, as are values with different spaces.

Does the download include every value?

Yes. The preview shows up to 12 rows, while the CSV includes every result.
